# Current-display transit: reviewed gateway connection

This EMPTY viewer uses the fixed `https://busan-trip-transit.kuirvana.workers.dev/v1/transit` endpoint and the same origin’s `/v1/walk` endpoint for explicitly requested approach walks. The fixed endpoint and both runtime instances stay inside the app IIFE. The index allows only its exact HTTPS host and the existing foot-routing host in connect-src; other CSP restrictions are intact. Current candidate local asset query versions are0.8.6. Configuration alone never enables transit: EMPTY startup, trip activation, storage restore and cached-page return stay disabled with budget0 and zero transit requests.

Dedicated gateway source SHA256 `2e93ccf48f23babb6dfae8880ea10ddf774babef60d5c134dea2d5b5de63bd2a` was deployed, with provider/caller credentials installed only as server Secrets. A real no-credential POST from the expected Origin returned401 with the exact CORS Origin and no-store. This proves the authentication boundary, not a positive provider route, browser CSP execution, usable rail/entrances or Android behavior. No credentials or real transit response data are bundled in the viewer.

## Request ownership and activation

`live-request.js` owns transport while `live-transit.js` owns parsing and current-display models. The app keeps both instances inside its IIFE, separate from trip/state, visit memory, source transport legs and FOSSGIS cache. Neither instance is exposed as an app console setter. There is no response-paste UI, response-file import, query/hash credential bootstrap, dynamic endpoint control or authentication bypass.

The reviewed endpoint is canonical HTTPS at exactly `/v1/transit`, without query/hash/userinfo. The exact connection policy is `connect-src https://routing.openstreetmap.de https://busan-trip-transit.kuirvana.workers.dev`. No wildcard or extra host is allowed. The user must enter the separately provided private caller connection code in the existing password control, then explicitly press enable. The panel becomes visible after loading a trip; selected-card transit is available at every edge index while enabled. A code alone or enable without a valid nonempty code sends nothing. The viewer never asks for a Kakao REST key. Caller codes must contain32–512 printable ASCII characters U+0021–U+007E (ordinary punctuation included), with no whitespace, controls or non-ASCII characters. The exact input is passed unchanged in the Authorization bearer field. Invalid input is rejected before owner activation or any request, kept in the password field and focused with a format message. Input is cleared only when activation successfully adopts it, and on disconnect/import/pagehide. Unexpected activation errors preserve input, disconnect partial request ownership and show a generic setup error without exposing exception text or asserting no transmission; no automatic retry occurs. Tokens are not stored or exported. Disposal releases references; physical memory erasure or immediate garbage collection is not claimed.

The session starts disabled with budget0. User enable latches a budget from1 through60 (the app control explicitly selects60). Each attempted transmission consumes one unit, even if it fails or times out. Used budget never decreases: date/composition changes, imports, disconnect/reconnect and re-enabling do not replenish it; it cannot be increased after first activation. No automatic retry exists. Current failed/settled edges cannot be resubmitted by rendering, repeated selection or repeated enable. Exhaustion marks queued/newly eligible edges with an explicit existing-data fallback and makes no additional request. This in-memory screen-session budget is **not an account-global spending, quota or rate limit**; new app sessions/devices and independent callers need separate server/account controls. No reset or retry control was added.

For each accepted request there is exactly one fetch, with POST JSON containing only numeric `start_x`, `start_y`, `end_x`, `end_y` from original pins. Headers are only JSON Content-Type and the Authorization bearer field; credentials are omitted, cache is no-store, redirect is error and referrer is omitted. Place names, dates, bookings, records, original JSON, user headers, extra request fields and upstream URLs are never sent. Timeout is fixed at15 seconds across headers/body. Content-Length and streamed decoded byte counts are bounded at2 MiB, UTF-8 is strict, and malformed/error bodies are rejected without displaying or logging them. No response cache/history, raw-body retention or alternative-route collection is created.

## Current screen lifetime and intent

Only currently displayed directed original-coordinate edges enter the queue. Identity includes both place IDs and both original coordinates, independent of row number, card selection or screen ratio. Reversed edges are independent. Endpoint kinds and approximate-pin flags also participate in invalidation. At most one transport is active; removal/context changes abort its AbortController and cancel its reader before subsequent work, while stale completions cannot acquire a current lifecycle token. Injected fakes that ignore abort are still rejected when they finish.

New trip/activation/import, date/composition change and disconnect dispose old results and tokens. Import starts by disconnecting before asynchronous file reading, including failed/cancelled imports. Import, disconnect and pagehide release the private token; pagehide also clears live DOM/layer references. A cached-page return renders owned data with transit disabled. Date/composition changes can queue their newly displayed eligible edges only while the explicitly enabled connection remains active; the session budget is shared.

Add/remove reconciles only changed/removed edges and preserves results and pending transport for unaffected displayed edges. Removed results cannot revive when an edge is later re-added. Each current edge settles once; parser rejection remains failure, not controller success. Render/onChange never synchronously starts another fetch, preventing recursive rendering and duplicate transmissions.

Automatic eligibility uses source transit/unknown intent across **all** indices; it is not capped at the first1/2/3 edges. Source composites containing bus/subway/rail are eligible. Explicit/source walking and foot candidates stay on the foot path automatically; closures are not automatically reclassified. Once configured/enabled, every selected edge can instead receive an explicit transit request, including unknown/new foot candidates beyond index3. Visit compositions such as bus/walk/rest never become physical transport modes. A straight-distance ordering/candidate threshold does not create a bus route. Failures show that existing lines/guide remain owned fallback data; no car or invented road fallback is introduced.

## Adapter and rail identity

The supplied contract remains `status: OK`, `routes[].properties`, `routes[].steps[].properties` with type/guidance/distance/time and optional stops/vehicles, plus `steps[].path.points` in longitude/latitude order. Only route0 is selected by the transport owner. The pure adapter can explicitly select another route, but does not retain raw bodies/alternatives. One longitude/latitude conversion creates immutable renderer coordinates. Existing step/vertex/regional/direction guards remain; route properties are not retained and no total journey time is fabricated.

`BUS` maps to bus, `SUBWAY` to subway, `WALKING` to walking. Access/exit/transfer walking and missing connectors/platform/entrance evidence remain explicit. Live results are always partial and field/road/operations unverified. They do not replace original pins or certify entrances. Response-derived models and decorated display legs have serialization guards and never enter storage/export callbacks. Source-owned objects remain unmodified.

Optional `railRules` defaults to an empty array; **no real aliases are preinstalled**. Each supplied rule must name `providerMode: SUBWAY`, one exact `vehicle: {name,type}` and nonempty source/reference, valid observedAt and `verification: source-verified` evidence. Rules are copied/frozen and duplicate identities are rejected. Only a step with exactly one matching vehicle/service identity becomes rail. Other subway services or the same name with a different vehicle type remain subway. Evidence appears in the shared guide model; access/platform/direction gaps stay unverified. Synthetic mapping tests establish only scoping. All real rail naming requires fresh, authorized current Kakao identity verification.

Map, schematic and selected guide consume the same accepted model and coordinate objects. Foot rendering runs between live overlays so asynchronous foot results cannot replace accepted transit or erase transit fallback notices. Live parsing never calls the FOSSGIS cache writer. Independently owned trip data, original geometry and existing caches retain their prior ownership.

## v0.8.6 manual current-edge approach walks

The accepted current transit card offers **접근·이탈·환승 도보 연결 (N회)**. N is the exact additional query count available for this action, bounded by current unqueried original-pin/provider-endpoint gaps and the remaining shared budget. More than20 gaps on one accepted edge blocks the action. It requires the existing connection enabled, an accepted current directed edge and no request in flight. Rendering, endpoint configuration and generic enable never start a walking batch. Primary transit automatic eligibility retains its existing behavior.

Both operations use the same in-memory caller and single-flight owner. Transit posts four coordinates to /v1/transit. A manual connector posts only four numeric original-pin/current-Kakao endpoint coordinates to /v1/walk on the SAME fixed gateway origin. The gateway chooses ONLY https://dapi.kakao.com/v2/routing/walk, GET with WGS84 input/output. No labels, dates, names, generic URLs, other providers or new secrets. Browser redirects fail; gateway redirects use manual and every3xx is rejected. Each attempt consumes the same monotonically used maximum60 page-session budget at dispatch, including failure/timeout. It is not an account-global quota. Failed connectors are held for the current edge, never retried by repeat actions or rendering.

Walk responses must have the bounded Kakao status:OK route/legs/steps shape, per-step guidance/metrics, valid WGS84 coordinates and consistent direction. Transit/car shapes are rejected as walking. No zero walk or total is invented. Successful steps receive unique connector IDs before/between/after the original bus/rail steps, preserving original ride IDs and coordinate arrays. Map and guide share the new immutable model. Remaining gaps are recomputed from all geometry, including walking endpoint snaps and internal gaps. Failure retains the bus path and affected missing gap. Detailed bus geometry can coexist with a missing approach walk. Two-coordinate paths have an explicit detail warning; greater vertex count alone proves no road alignment.

Date/composition/import/disconnect and directed-edge removal discard connectors with existing ownership and ignore late replies. Unchanged current edges keep results. Date/composition changes keep the explicitly enabled same-page connection; import/disconnect/pagehide releases the caller. **Tab visibility alone does not disconnect.** Full reload cannot restore the caller or live responses. No live walking data enters state, localStorage, history, foot-cache callbacks or exports; all model branches have JSON guards. Original pins, trip, reservations and existing independently owned FOSSGIS foot caches stay separate. Reference release is not physical memory erasure.

## v0.8.7 source-step recheck and boundary diagnostics

Connector insertion and replacement of an existing walking step are different operations. The selected live card offers **이 도보 1회 재확인** for each original WALKING/access/exit/transfer/standalone source step. Plans and rendering do not fetch. This action does not guarantee a more detailed route.

The target is bound to the current directed edge, expected model, stable source step ID and source coordinates. Only original current base/inserted walking steps qualify; generated replacement children cannot recursively request again. Attempted, failed or exhausted source IDs remain held for the context, including remove/re-add. Imports, context changes and disconnect retain existing cancellation/disposal rules. A dispatched failure never replenishes the budget.

Only the documented route.legs[].steps[].path.points coordinates are parsed. The first/last supplied points must correspond to the selected endpoints within the existing0.5m identity tolerance. This conservative check can reject a snapped response; it is not an official provider precision bound or proof of a valid entrance. Invalid, reversed, stale, late or mismatched responses retain the old geometry with no retry. No route-option/high-resolution switch, artificial point, endpoint fusion or speculative geometry field is added.

Accepted geometry replaces only the selected walking step. Other step IDs/coordinate arrays, all rides, source pins and accepted connectors stay intact. The deterministic display rebuild includes both insertions and replacements, so later insertions cannot revive an old replaced step. Remaining boundaries are recomputed and remain explicitly unverified. Each step exposes supplied vertex count, a two-vertex observation, summed supplied-polyline length, provider distance and their numerical difference. Two points can be consistent with a short straight segment; neither two points, more points, nor distance agreement establishes actual road or entrance alignment. The card reports same_coordinates or different_coordinates without claiming improved detail. Current child metadata always has detailImprovementVerified=false.

Residual gaps retain stable boundary IDs, pin-to-step/step-to-step/step-to-pin type, adjacent step IDs and observed separation with physicalAccessVerified=false. Runtime additions remain ephemeral and excluded from trip, localStorage, foot-cache callbacks and exports. Existing source/base ownership supports rebuilding without retaining a response-version history. No gateway, account, secret, permission, dependency or CSP change is required.
